Why MPP.sol exists

Stripe and Tempo Labs co-authored the Machine Payments Protocol — an IETF-draft formalization of HTTP 402 for machine-to-machine payments. Production settlement methods today: Tempo (their EVM L1), Stripe cards, Lightning. Not Solana.

Solana is the highest-throughput L1 with deep USDC liquidity, sub-cent fees, and the largest deployed base of agents and on-chain automation. MPP.sol adds Solana as a settlement adapter — and adds something no other MPP adapter has: a CPI primitive that lets one Solana program atomically pay for and consume an off-chain MPP-priced resource via cross-program invocation.

EVM-based MPP adapters can't match the CPI primitive — Solana's atomic multi-instruction transaction model and Ed25519 precompile pattern make off-chain-signed message verification cheap on-chain in ways EVM doesn't.

Architecture

client │ ▼ ┌─────────────┐ │ server │ Hono / FastAPI middleware │ 402 ──────►│ emits Solana payment challenge └─────────────┘ │ client builds + signs Solana tx (USDC transfer + Memo nonce binding) │ ▼ ┌─────────────┐ │ Solana │ optional on-chain composition: │ mppsol_* │ mppsol_session escrow + debits, │ programs │ mppsol_cpi for atomic └─────────────┘ pay-and-consume in other programs

solana-direct (one-shot)

Each request gets a fresh Solana tx: USDC transfer to the server's token account + Memo with the server's nonce. No on-chain program required. Mainnet-shippable today.

solana-session (streaming)

Open a session PDA on-chain with escrowed USDC + an authorized signer key. Sign 104-byte off-chain debits per request; server batches and settles on-chain. Sub-cent per-request marginal cost.

CPI primitive

Other Solana programs CPI into mppsol_cpi to pay for off-chain resources atomically. The novel piece — EVM MPP adapters can't do this.

Spec-conformant

Implements the IETF-draft wire format faithfully. Will upstream a Solana settlement-method registration once the spec stabilizes.

Quickstart — pay your first 402 in ~60 seconds

Spin up a paid endpoint, then pay it. Both halves use a real Solana devnet payment in USDC.

1. Run the server (terminal 1)

git clone https://github.com/mppsol/server
cd server
npm install hono @hono/node-server
export MPPSOL_RECIPIENT=<your-devnet-USDC-token-account>
bun run examples/hono.ts
# Listening on http://localhost:3000

2. Pay it (terminal 2)

git clone https://github.com/mppsol/agent
cd agent
npm install @solana/web3.js @solana/spl-token bs58
export MY_USDC_ATA=<your-devnet-USDC-token-account>
bun run examples/pay-direct.ts
# → Status: 200
# → Body: Why don't scientists trust atoms? Because they make up everything.
# → Receipt: Payment scheme="solana-direct", tx="...", slot="..."

3. (optional) Try session mode

# Open a session PDA on devnet with 1 USDC escrowed
git clone https://github.com/mppsol/cpi
cd cpi && export MPP_SERVER_PUBKEY=<server-wallet>
bun run examples/open-session.ts

# Then pay against it from the agent
cd ../agent
export MPPSOL_SESSION=<from-above>
export SIGNER=../cpi/authorized-signer.json
bun run examples/pay-session.ts
